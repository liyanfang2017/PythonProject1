# 软件测试用例书写规范
## 用例组成字段
1、用例标题：简短清晰描述测试场景
2、前置条件：执行这条用例之前需要满足的环境、账号、数据条件
3、操作步骤：一步一步，详细可复现
4、预期结果：执行操作后，系统应该返回的结果

## 测试场景覆盖要求
每个功能需求生成用例时，必须包含：
1. 正向正常场景
2. 反向异常场景（非法输入、空输入）
3. 边界值场景（最大长度、最小长度、临界数值）
4. 权限场景（不同角色账号访问）

## 示例范本：用户登录功能
>需求：账号密码登录页面，账号密码正确登录成功；密码错误提示账号或密码错误。

【用例1】
用例标题：正确账号+正确密码，登录成功
前置条件：已注册用户账号
操作步骤：
1、打开登录页面
2、输入正确账号
3、输入正确密码
4、点击登录按钮
预期结果：跳转首页，登录成功

【用例2】
用例标题：正确账号，错误密码登录
前置条件：已注册用户账号
操作步骤：
1、打开登录页面
2、输入正确账号
3、输入错误密码
4、点击登录按钮
预期结果：页面提示：账号或密码错误
