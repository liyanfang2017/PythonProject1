接口自动化框架
api_tests 框架设计方案解析

  一句话总览（面试开场）

  ▎ 基于 pytest + httpx 自建的五层黑盒接口自动化框架：配置层 → 公共工具层 → 接口对象层 → 契约模型层 → 用例/场景层，配合 Allure 报告、Schemathesis 契约测试和 Locust 性能测试，覆盖功能、契约、安全、性能四个维度。

  分层架构

  ┌─ testcases/   用例层：一条用例=一个测试点，只做"调接口+断言"
  │    ├─ smoke/ auth/ todos/ orders/ payments/ files/ stream/ security/
  │    ├─ contract/      Schemathesis 契约测试（基于 OpenAPI）
  │    └─ scenarios/     业务流编排：注册→下单→支付→对账→导出
  ├─ api/         接口对象层：每模块一个 Api 类（类 PageObject 思想）
  │               URL、请求报文、头信息等"接口细节"只允许出现在这一层
  ├─ schemas/     契约模型层：pydantic 模型与服务端响应结构对齐
  ├─ common/      公共层：client / token_manager / assert_util / data_factory / sse_util / webhook_util
  └─ config.py    配置层：.env.test + 环境变量覆盖，frozen dataclass 不可变

30 秒口述版（面试背这段）

  ▎ 我用的框架是 pytest + httpx 自建的分层框架。整体分五层：配置层用 dotenv 做多环境切换；公共层封装了统一 HTTP 客户端——统一超时、请求日志、Allure 附件、敏感头脱敏；令牌管理器按用户维护会话，基于 httpx.Auth 实现了 401
  ▎ 自动刷新 token 并重放请求；接口对象层把 URL 和报文细节与用例解耦，接口变更只改一处；断言层针对统一响应信封封装了成功/业务异常/参数校验三类断言，响应自动反序列化成 pydantic 模型做类型安全断言。数据上用 Faker 
  ▎ 保证用例隔离可并行，YAML 做边界值数据驱动。执行上有环境守卫快速失败、mark 分层跑冒烟和回归、xdist 并行。除此之外还用 Schemathesis 做契约测试、Locust 做性能，已知服务端缺陷用 xfail 登记保证闭环。
