# 四者核心差异总结

1. **Redis（K‑V + PubSub）**

- ✔️擅长：缓存、幂等、token 黑名单；简单广播通知。
- ❌PubSub 没有消息存储，离线订阅者丢失消息，**不要拿来做业务队列**。

2. **Redis‑Streams**

- ✔️复用 Redis 服务，不用部署新组件；具备消息持久、消费组、ack。
- ❌内存受限，消息量不能无限大；高级特性弱于 RabbitMQ/Kafka。

> 
> 使用场景：中小型项目快速异步解耦。

3. **RabbitMQ**

- ✔️强大路由，交换机、死信队列、延迟队列，业务场景友好，消息可靠性高。
- ❌高吞吐弱于 Kafka，大量消息堆积性能下降。

> 
> 使用场景：业务任务队列，需要复杂路由、重试、死信。

4. **Kafka**

- ✔️分区、高吞吐、海量消息堆积，数据流，日志采集。
- ❌太重，不适合复杂业务路由，不适合传统任务队列。

> 
> 使用场景：大数据，日志流，高并发海量消息。

# 选型快速判断

1. 只想少部署组件、中小流量异步解耦：**Redis Streams**
2. 业务消息，需要灵活路由、死信、重试：**RabbitMQ**
3. 日志、数据流、百万级高吞吐：**Kafka**
4. 缓存、幂等键、token 黑名单、简单通知广播：**Redis KV + PubSub**

> 
> 演进路径：初期 Redis‑Streams；业务变复杂迁移 RabbitMQ；海量数据流迁移 Kafka。
