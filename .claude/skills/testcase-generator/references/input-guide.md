# 输入解析指南

四种输入的识别特征、解析要点与常见坑。主流程见 SKILL.md，本文件按需加载。

## 1. OpenAPI 文档（Swagger / OpenAPI 3.x）

**识别特征**：含 `openapi:` 或 `swagger:` 顶层键（JSON/YAML）；有 `paths`、`info`、`definitions`/`components` 等结构；内容为端点与 schema 定义。

**解析要点**：

- 先提取端点清单：`path` + `method` + `summary`/`tags`，形成总览再逐个深入
- 每个端点提取：参数（`in`/`type`/`required`/`enum`/`maxLength`）、请求体 schema、各状态码响应定义、错误码说明
- 用例中引用参数名时，回查原文出处（端点+参数位置），供 Step 3 溯源

**常见坑**：

- **版本差异**：Swagger 2.0 的 schema 定义在顶层 `definitions`，OpenAPI 3.x 在 `components/schemas`；2.0 的请求体是 `parameters` 中 `in: body`，3.x 是 `requestBody`。解析前先确认版本，不要用一套路径硬套
- **`$ref` 展开**：引用必须展开后再校验「字段是否存在」，否则会把 `$ref` 指针名当字段名生成用例；遇到**循环引用**（A→B→A）只展开一层并标注深度，不无限递归
- **缺 `responses` 定义**：不猜响应结构，列入 G1 提问清单
- **file:// 或 URL 形式的引用**：一律不跟随（禁止网络访问），列入缺失清单

## 2. 需求 PRD 文本

**识别特征**：含业务背景/目标/用户角色描述、业务流程或规则、功能描述或验收标准；常见关键词：需求、背景、目标、用户故事、验收标准。

**解析要点**：

- 提取：功能模块划分、业务规则（含约束与边界）、角色与权限、验收标准
- 每个可测点记录**需求原文出处**（章节或原句），供溯源与【需确认】标注

**常见坑**：

- **纯截图型 PRD（图片无文字层）**：无法可靠提取控件与规则时，明确告知用户无法识别的部分，请求文字补充或更清晰截图；**不凭轮廓猜控件名**
- **PRD 与设计稿冲突**（同一控件名称/规则不一致）：不擅自取舍，列入 G1 提问清单请用户裁决
- 验收标准缺失的功能点：相关用例标题标【需确认】

## 3. 技术方案文档

**识别特征**：含架构/技术选型描述、表结构(DDL)、状态机或时序图、性能/容量/降级/灰度等非功能约束；常见关键词：架构、选型、DDL、时序、缓存、MQ、灰度、降级、QPS。

**解析要点**：

- 按**技术变更点/风险点**提取可测点（新增表、状态流转、降级策略、超时重试），**不是**按业务场景提取
- 从技术约束提取边界值素材：字段长度、超时/重试次数、限流阈值；异常场景素材：依赖失败、降级路径

**常见坑**：

- 业务验收标准缺失时，用例标题必须标【需确认】，不得自行补业务语义
- DDL 中的字段与线上接口字段可能不一致：接口维用例以 OpenAPI 为准，DDL 仅作边界值素材，两者冲突时列入提问清单

## 4. 设计稿（截图 / 本地图片）

**识别特征**：PNG/JPG 图片，内容为页面布局、控件、文案。

**解析要点**：

- 只认**可见控件原文**：按钮文案、输入框 placeholder、列表列名、提示文案——逐字摘录，不改写
- 提取页面结构（区块划分）与状态提示（成功/失败/空态文案）

**常见坑**：

- **Figma / 墨刀等在线设计链接一律拒绝**：本 skill 禁止网络访问；请用户导出截图（整页 + 关键状态各一张）或用文字描述页面
- 图片模糊、控件文字不可辨认：说明具体情况，请求更清晰截图或文字补充；**不猜控件名**
- 多张截图属于同一页面的不同状态（正常/空态/报错）：合并为一个可测点的多状态，不拆成多个模块
